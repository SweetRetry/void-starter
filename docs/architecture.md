# Architecture

Void Starter is a Turborepo + pnpm workspace with one app and two shared packages. The app deploys as a single Cloudflare Worker.

## Workspace

| Path                         | Owns                                                                                     |
| :--------------------------- | :--------------------------------------------------------------------------------------- |
| `apps/web`                   | The TanStack Start app: routes, server functions, `/api/*` routes, schema and migrations |
| `packages/ui`                | shadcn/ui components on Base UI, Retry tokens (`globals.css`), shared hooks and `cn`     |
| `packages/typescript-config` | Shared tsconfig presets                                                                  |

`apps/*` own entry points and app-specific business code. `packages/*` hold only what several apps already share, never what might be reused someday. Packages are consumed through their public `exports`.

## Inside `apps/web`

```text
apps/web/
  src/routes/             file routes: pages, layouts and /api/* server routes
  src/server/             server-only modules (*.server.ts) and server functions (*.functions.ts)
  src/components/         app components built from @workspace/ui
  src/lib/                code shared by browser and server (schemas, stream parser)
  db/schema.ts            Drizzle schema: app tables and Better Auth tables
  db/migrations/          generated by `pnpm db:generate`, applied by `void deploy`
  env.ts                  typed server env (defineEnv)
  void.config.ts          Worker settings, AI Gateway, observability
  vite.config.ts          voidPlugin() before tanstackStart()
```

- **Server functions** (`createServerFn`) serve the app's own pages. They validate input with the same Zod schema the form uses (`src/lib/note-input.ts`).
- **`/api/*` server routes** serve anything that isn't a page RPC: binary uploads and downloads, streams, and Better Auth at `/api/auth/*`. Their errors follow [api.md](api.md).
- **`*.server.ts`** modules never reach the browser bundle. TanStack Start's import protection fails the build if a client-reachable file imports one outside a server function handler.

## Request path

```text
browser ─▶ Worker (Void + TanStack Start)
             ├─ pages and server functions ─▶ D1 (void/db)
             ├─ /api/notes/:id/attachment  ─▶ R2 (void/storage)
             ├─ /api/notes/:id/summary     ─▶ AI Gateway ─▶ Workers AI (void/ai)
             └─ /api/auth/*                ─▶ Better Auth ─▶ D1
```

## Decisions

Each decision names the alternative it beat, so a later change can tell whether the reason still holds.

- **Void in framework mode, with TanStack Start.** Void infers bindings from imports (`void/db` means D1, `void/storage` means R2, `void/ai` means Workers AI), provisions them on deploy and applies migrations. TanStack Start brings routing, SSR, server functions and typed loaders. Void's own pages router was the alternative. TanStack Start was preferred for its ecosystem and for route types shared by loaders and links. The cost: `void/auth` doesn't run in framework mode, so Better Auth is wired by hand (`src/server/auth.server.ts`).
- **One Worker, no separate API server.** Pages, server functions and `/api/*` share one deploy, one origin and one session cookie. A separate API server would add CORS, a second deploy and a second set of secrets for no gain at this size.
- **D1 is the only database.** It's serverless SQLite on the same network as the Worker, and Void provisions it with zero config. D1 has no interactive transactions, so the Better Auth adapter runs with `transaction: false`. Add Hyperdrive and Postgres only when the data needs it.
- **Better Auth.** It owns sessions, email and password, and OAuth. Social providers turn on only when both of their credentials exist, so a fresh clone never shows a broken button.
- **Base UI under shadcn/ui.** The components were regenerated on the `base-nova` preset. Forms use shadcn's `Field` with react-hook-form's `Controller`; Base UI has no `Form` registry item.
- **Retry is the design language.** [DESIGN.md](../DESIGN.md) is the spec and `packages/ui/src/styles/retry.css` holds its tokens. Both are this repo's own files; change them like any other design decision. Retry's component deltas are reapplied by a codemod (`scripts/apply-retry-deltas.js`) after each shadcn regeneration.
- **Vite+ for format, lint and test.** One toolchain (`vp fmt`, `vp lint`, `vp test`) replaces Biome, oxlint config files and a bare Vitest. `@shadcn/lint` rules run inside `vp lint`.
- **RFC 9457 for every `/api/*` error.** One helper builds every error body, and `instance` carries the `cf-ray` id, so a user's report finds the request in Workers Logs ([api.md](api.md)).

## Data and migrations

The schema lives in `apps/web/db/schema.ts`. Change it, then generate a migration:

```sh
pnpm db:generate
```

`pnpm dev` applies pending migrations to local D1 before it starts (`pnpm db:migrate` does it on demand). `pnpm deploy` applies them to production. Never edit the database by hand.

## Extension points

These products aren't wired in. Void exports a module for each:

- KV: `void/kv`
- Queues: `void/queues`
- Email: `void/email`
- Durable Objects: `void/durable`
- Crons: one file per job in `crons/`

Add one as its own slice, the way notes, attachments and summaries are separate.
